1 — The two halves of the map

Both halves are scanned by the CLI now — deterministic, cheap, runnable in CI. An agent only touches what the code cannot decide.

deterministic CLI skill / agent measured from a real response

The dashed line in the previous version — the two halves unjoined — is gone. link matches endpoints on METHOD + normalized path, and on the suffix when the FE goes through a gateway with its own prefix.

2 — The FE workflow: from a repo to an answer

The CLI reads the whole repo and decides what a machine can decide. The agent opens only the files the CLI gave up on — usually a few dozen lines, not a few thousand files.

deterministic — runnable in CI agent — only what the code cannot decide

The agent never edits .apimap directly. It only writes hints.json; ids are still derived by the code. That is what keeps a re-scan from becoming a whole-file diff in git.

3 — The probe loop: the only place that guarantees “true to the live API”

A static scan sees only what the code declares. Probe runs the endpoint for real — but inside the project's own test suite, so it sits on a test database.

Only a 2xx response with a body is learned from. A 401/500 body is an error envelope — writing it into the map would record the wrong contract, so it goes to a skipped list with a reason.

4 — The architecture as-is

One headless core, four entry points. src/core/ knows neither React nor Node — so the app, the MCP server and the CLI all share one copy.

Two separate formats is a decision, not duplication: a hand-built flow has to keep the node positions someone dragged; a machine-generated map that stored coordinates would turn every re-scan into a whole-file diff — and nobody drags 300 nodes by hand. Compare jsoncrack: it never stores x/y; elkjs computes the layout in a web worker.

6 — The three confidence levels

A general scanner resolves only part of the picture. A map that cannot say how sure it is gets trusted more than it deserves.

exact the url is a literal and the verb is visible at the call site — axios.post('/api/users').
inferred one half was derived: a variable base url, the implicit GET of fetch, or a value supplied by hints.
guess the path was dug out of a larger expression. Good enough to narrow a search, not to conclude.
observed the response was measured in a real run against test data. This is the only level that can claim to be true to the live API.
Unresolved certainly HTTP, but the url could not be resolved. Never dropped silently — it is the agent's work list.
